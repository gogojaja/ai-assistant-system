## ADR-001 五角色 → 三角色拆分

- **状态**：已采纳
- **背景**：PRJ-001（2026-08-05~09-05，25 人·日）将五角色收敛为三角色（闲聊/办公/日程）。
- **决策**：保留 `chat-assistant`（闲聊/记忆/委派/起草）、`office-assistant`（Word/Excel/PPT/文件）、`life-assistant`（日程/健康/旅行/锻炼/工作/提醒）；统一经 `shared` 层共享基础能力与配置。
- **理由**：降低角色耦合与维护成本，符合"最小业务角色"约束；禁止项明确"新增业务角色"。
- **影响**：移除原 4 号文件助手独立路由，文件消息并入 office；回调 `callback_server.py` 硬编码助手 src 路径需随角色增减同步修改。
- **备选**：维持五角色 → 否决（超出预算与禁止项）。

## ADR-002 文档处理外部化（PPTAgent / dashi-ppt）

- **状态**：已采纳
- **背景**：本地 PPT/摘要生成质量不足，但禁止项含"Docker / 数据迁云端"。
- **决策**：PPT 生成优先调用**已部署的外部 PPTAgent 服务（HTTP）**，其次 dashi-ppt（Node HTML→PPTX），本地 `core.ppt_generator` 兜底；摘要优先委托外部 LLM。本项目**本环境不部署 Docker、不持有智谱 key**。
- **理由**：外部依赖隔离 + 最小权限，兼顾质量与约束合规。
- **影响**：外部服务不可达时自动降级本地；需配置外部服务地址与健康检查（`external_doc_tools.py`）。
- **备选**：本环境部署 Docker 跑 PPTAgent → 否决（违反禁止项）。

## ADR-003 推理后端三可切换 + 云端优先降级本地

- **状态**：已采纳（本地双后端部分被 ADR-007 取代）
- **背景**：需兼顾生成质量（云端）与离线可用性（本地）。
- **决策**：`backend_utils.call_api` 统一抽象，配置驱动 free-api-hub（云端优先）/ llama.cpp（localhost:8080）/ Ollama（localhost:11434）切换；云端不可达自动降级本地。
- **理由**：可用性 + 质量权衡；敏感数据仅本地加密不迁云端。
- **影响**：模型进程闲置 30min SIGSTOP、请求到达 SIGCONT；内存超 8GB 自动重启。
- **变更**：本地推理后端已收敛为单一 ollama 容器，llama.cpp 聊天服务（llama-server :8080）于 2026-08-17 移除，详见 ADR-007。

## ADR-004 跨会话记忆本地加密、不迁云端

- **状态**：已采纳
- **背景**：REQ-034 需持久化用户事实（名字/生日/邮箱/偏好）。
- **决策**：记忆 AES 加密留存 `assistants/chat-assistant/memory/`，密钥隔离 `.env` 不入库；用户 `clear` 可清除。
- **理由**：数据最小化 + 加密，满足安全架构与隐私约束。
- **影响**：记忆文件随 open_id 维度存储，与对话历史同目录。

## ADR-005 双环境隔离（测试 / 主）

- **状态**：已采纳
- **背景**：需独立验证环境，避免误改主环境。
- **决策**：测试环境 `/Volumes/BR256G/ai-assistant-system/`（端口 5101/5103，APP_ID `cli_aa9c870de6799bb4`）；主环境 `/Users/gogo/ai-assistant-system/`（端口 5001/5002/5003）。端口分离、目录分离、凭证分离。
- **理由**：环境隔离铁律；禁止操作 5001/5002/5003。
- **影响**：本会话仅可管理测试环境端口；主环境操作需独立授权。

## ADR-006 主动提醒守护线程轮询

- **状态**：已采纳
- **背景**：REQ-037 需到期主动推送。
- **决策**：`callback_server` 启动守护线程每 60s 轮询 `check_reminders(within_minutes=30)`，按 `REMINDER_TARGET_ID` 去重推送。
- **理由**：轻量轮询 + 模型进程按需唤醒，兼顾实时性与资源占用。
- **影响**：提醒目标需配置 open_id 或环境变量。

## ADR-007 本地推理统一为单一 ollama 容器（移除 llama.cpp 聊天服务）

- **状态**：已采纳（2026-08-17）
- **背景**：本机多项目（测试环境 `/Volumes/BR256G/ai-assistant-system`、主环境 `/Users/gogo/ai-assistant-system`）原各起一套 llama-server（:8080）作本地兜底推理；推理审计发现 llama-server 与 ollama **权重共享同一 ollama blob 存储**，仅一活跃实例真正占用资源，二者属重复部署而非独立能力。
- **决策**：本机所有项目只保留一套 ollama 容器（:11434，`qwen2.5:7b`）作为唯一本地推理后端；移除 llama-server 及其专用脚本（`scripts/start-llama.sh`、`scripts/stop-llama.sh`、`scripts/benchmark_llama.sh`）；`config/settings.yaml` 改为 `backend: ollama`。`backend_utils.call_api` 原生支持 ollama，无需改业务代码。
- **理由**：消除重复权重部署与端口占用，统一运维面；`shared/whisper.cpp` 内嵌的 llama.cpp 属语音识别依赖，**不在此列、禁止改动**。
- **影响**：配置 `backend` 默认 ollama；`diagnose.py` 服务项由 `llama-server:8080` 改为 `ollama:11434`；监控脚本 `monitor_services.sh` 不看护 llama-server（已无引用）；回滚需恢复 settings.yaml 与三脚本（`git revert` 本提交）。
