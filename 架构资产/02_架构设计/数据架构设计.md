## 1. 文档概述

五角色 AI 助理系统采用"无数据库 + 本地文件存储 + Fernet 对称加密"的数据架构方案。系统不依赖任何外部数据库服务（MySQL、PostgreSQL、MongoDB 等），全部业务数据以 JSON、YAML、TXT 等文件格式持久化在本地文件系统中，敏感数据通过 cryptography.fernet 进行加密保护。

本文档对系统的数据实体、数据字典、存储策略、数据流转、生命周期管理、安全策略和备份恢复机制进行全面设计，覆盖以下五个角色的数据域：

| 角色 | 数据域 | 核心数据实体 |
|------|--------|-------------|
| 1号AI 闲聊助理 | 对话与检索 | ChatHistory、CustomPrompt、SearchArchive |
| 2号AI 办公助理 | 文档处理 | OfficeFile、MonitoredFolder |
| 3号AI 生活助手 | 生活管理 | Schedule、HealthRecord、TravelPlan、WorkoutPlan、WorkTask |
| 4号AI 文件助理 | 文件管理 | FileWhitelist |
| 5号AI 系统助理 | 系统运维 | SystemConfig、BackupRecord、ServiceLog |

设计目标如下：

- **数据完整性**：每条用户数据通过 open_id 实现隔离，文件操作采用原子写入策略
- **数据保密性**：对话历史等敏感数据使用 Fernet 加密，密钥文件权限 0600
- **数据可恢复性**：每日自动备份，RTO <= 30 分钟，RPO <= 24 小时
- **数据可追溯性**：所有业务记录包含 created_at 时间戳，备份记录包含时间戳与文件大小
- **架构简洁性**：零数据库依赖，部署仅需 Python 运行时，降低运维复杂度

## 3. ER 模型（文字描述）

系统包含 11 个核心数据实体，以 User 为聚合根，其余实体通过 open_id 与 User 建立一对多关系。以下按业务域分组描述各实体的属性、关系和基数。

### 3.1 User（用户）

| 属性 | 类型 | 说明 |
|------|------|------|
| open_id | String (PK) | 飞书用户唯一标识，由飞书平台分配 |
| custom_prompt | Text | 用户自定义系统提示词，存储于 `prompts/{open_id}.txt` |

**关系**：一个 User 拥有 0..1 条 ChatHistory、0..1 个 CustomPrompt、0..N 条 Schedule、0..N 条 HealthRecord、0..N 条 TravelPlan、0..N 条 WorkoutPlan、0..N 条 WorkTask、0..1 个 KnowledgeIndex。

### 3.2 ChatHistory（对话历史）

| 属性 | 类型 | 说明 |
|------|------|------|
| open_id | String (FK→User) | 用户标识，同时作为文件名组成部分 |
| messages | Array\<Message\> | 消息列表，最多保留 10 轮（20 条消息） |
| messages[].role | String | 消息角色：user / assistant / system |
| messages[].content | String | 消息文本内容 |
| messages[].timestamp | String | 消息时间戳，ISO 8601 格式 |
| created_at | String | 首次对话时间 |
| updated_at | String | 最近更新时间 |

**关系**：与 User 为多对一关系。文件命名规则为 `{open_id}_history.json`，加密后为 `{open_id}_history.json.enc`。

**约束**：MAX_HISTORY_TURNS = 10，每轮包含 user + assistant 两条消息，超出时自动裁剪保留最近 20 条。

### 3.3 KnowledgeDoc（知识库文档）

| 属性 | 类型 | 说明 |
|------|------|------|
| doc_id | String (PK) | 文档标识，格式为 `{filename}#{paragraph_index}` |
| file | String | 源文件名 |
| text | Text | 段落原文 |
| len | Integer | 分词后 token 数 |
| freq | Map\<String, Integer\> | 词项频率表 |

**关系**：属于全局知识库或某 User 的私有知识库。倒排索引存储于 `knowledge_index.json`（全局）或 `knowledge_index_{user_id}.json`（per-user）。

**检索算法**：BM25（K1=1.5, B=0.75），中文采用字符二元组分词，完整短语加权 x2.5。

### 3.4 Schedule（日程）

| 属性 | 类型 | 说明 |
|------|------|------|
| id | String (PK) | 8 位 UUID 截断标识 |
| title | String | 日程标题 |
| time | String | 日程时间，ISO 8601 格式 |
| location | String | 地点（可选） |
| notes | String | 备注（可选） |
| created_at | String | 创建时间 |

**关系**：与 User 为多对一关系（当前为全局存储，设计上按 open_id 扩展）。存储于 `data/life/schedules.json`。

### 3.5 HealthRecord（健康记录）

| 属性 | 类型 | 说明 |
|------|------|------|
| type | String | 数据类型：weight / steps / sleep / heart_rate |
| value | Float | 数值（体重 kg / 步数 / 睡眠 h / 心率 bpm） |
| date | String | 记录日期，ISO 8601 格式 |
| created_at | String | 创建时间 |

**关系**：与 User 为多对一关系。存储于 `data/life/health.json`。支持日报、周报、月报聚合统计。

### 3.6 TravelPlan（旅行计划）

| 属性 | 类型 | 说明 |
|------|------|------|
| id | String (PK) | 8 位 UUID 截断标识 |
| destination | String | 目的地 |
| start_date | String | 出发日期 |
| end_date | String | 返回日期（可选） |
| notes | String | 备注 |
| activities | Array\<{item, date}\> | 行程活动列表 |
| packing_list | Array\<{item, checked}\> | 行李清单（checked 为布尔值） |
| created_at | String | 创建时间 |

**关系**：与 User 为多对一关系。存储于 `data/life/travels.json`。

### 3.7 WorkoutPlan（锻炼计划）

| 属性 | 类型 | 说明 |
|------|------|------|
| id | String (PK) | 8 位 UUID 截断标识 |
| name | String | 计划名称 |
| exercises | Array\<{name, sets, reps}\> | 训练项目列表 |
| logs | Array\<{date, note}\> | 训练记录列表 |
| created_at | String | 创建时间 |

**关系**：与 User 为多对一关系。存储于 `data/life/workouts.json`。

### 3.8 WorkTask（工作任务）

| 属性 | 类型 | 说明 |
|------|------|------|
| id | String (PK) | 8 位 UUID 截断标识 |
| title | String | 任务标题 |
| status | String | 状态：todo / doing / done |
| priority | String | 优先级：高 / 中 / 低 |
| deadline | String | 截止日期（可选） |
| notes | String | 备注 |
| created_at | String | 创建时间 |

**关系**：与 User 为多对一关系。存储于 `data/life/works.json`。

### 3.9 FileWhitelist（文件访问白名单）

| 属性 | 类型 | 说明 |
|------|------|------|
| assistant | String (PK) | 助手标识：chat / office / file / dev |
| allowed_paths | Array\<String\> | 允许访问的目录路径列表 |
| denied_paths | Array\<String\> | 禁止访问的目录路径列表 |

**关系**：独立配置实体，不与 User 关联。存储于 `config/whitelist.yaml`。

### 3.10 SystemConfig（系统配置）

| 属性 | 类型 | 说明 |
|------|------|------|
| location | String | 用户所在城市，用于天气查询默认值 |
| backend | String | 本地推理后端：llama.cpp / ollama |
| ollama_model | String | Ollama 模型名称 |
| llama_port | Integer | llama.cpp 服务端口 |
| ollama_port | Integer | Ollama 服务端口 |
| file_bot_port | Integer | 文件助理服务端口 |
| max_memory_gb | Integer | 模型最大内存占用（GB） |
| idle_timeout_minutes | Integer | 空闲超时挂起时间（分钟） |
| check_interval_seconds | Integer | 状态检查间隔（秒） |
| callback_port | Integer | 飞书回调服务端口 |
| code_api_port | Integer | 代码 API 服务端口 |
| dashboard_url | String | 监控面板 URL |
| api_keys | Map\<String, String\> | 第三方 API 密钥集合 |

**关系**：独立配置实体。存储于 `config/settings.yaml`。

### 3.11 BackupRecord（备份记录）

| 属性 | 类型 | 说明 |
|------|------|------|
| archive_path | String (PK) | 备份文件完整路径 |
| timestamp | String | 备份时间戳，格式 YYYYMMDD_HHMMSS |
| size | String | 备份文件大小（人类可读） |
| retention_days | Integer | 保留天数 |

**关系**：独立运维实体。备份文件存储于外部卷，命名规则为 `ai-assistant-system_{timestamp}.tar.gz`。

## 5. 存储策略

### 5.1 当前方案：本地文件 + Fernet 加密

系统当前采用纯文件存储方案，不引入任何数据库依赖。该方案在架构策略分析阶段评估得分为 4.50，适用于单机部署、用户规模 < 100 的场景。

| 维度 | 评估 | 说明 |
|------|------|------|
| 部署复杂度 | 优 | 零数据库依赖，仅需 Python 运行时 |
| 读写性能 | 良 | 单用户文件 < 100KB，JSON 读写延迟 < 5ms |
| 数据隔离 | 良 | 按 open_id 文件名隔离，无跨用户读取 |
| 并发控制 | 中 | 依赖文件锁，不适合高并发写入 |
| 查询能力 | 中 | 无索引查询，知识库通过 BM25 倒排索引弥补 |
| 事务支持 | 差 | 无 ACID 事务，异常中断可能丢失最后一条写入 |
| 扩展性 | 差 | 难以水平扩展，文件数量随用户线性增长 |

**加密机制**：敏感数据（对话历史）通过 `shared/crypto.py` 模块使用 Fernet 对称加密。加密后的文件内容为 base64 编码的密文字符串（以 `gAAAA` 开头），原地覆盖原始文件。

## 8. 数据安全策略

### 8.1 Fernet 对称加密

系统使用 Python cryptography 库的 Fernet 实现对敏感数据的对称加密。Fernet 基于 AES-128-CBC 加密和 HMAC-SHA256 签名，提供保密性和完整性双重保障。

**加密范围**：

| 数据类别 | 是否加密 | 原因 |
|----------|----------|------|
| 对话历史 | 是 | 包含用户隐私对话内容 |
| 飞书凭证（.env） | 否（文件权限保护） | 由 .gitignore 排除，文件系统权限控制 |
| 加密密钥（.crypto_key） | 否（自身即为密钥） | 文件权限 0600，.gitignore 排除 |
| 生活数据 | 否 | 非高敏感数据，明文便于调试和迁移 |
| 知识库文档 | 否 | 公开知识内容 |
| 系统配置 | 否 | 由 .gitignore 排除版本控制 |

**加密流程**（`shared/crypto.py`）：

```python
# 加密：明文 → Fernet.encrypt → base64 密文 → 覆盖写入文件
encrypt_text(plaintext)  →  "gAAAAABm..."
encrypt_file(filepath)   →  原地覆盖为密文
encrypt_json(obj)        →  序列化后加密

# 解密：base64 密文 → Fernet.decrypt → 明文
decrypt_text(ciphertext)  →  "原始文本"
decrypt_file(filepath)    →  原地恢复明文
decrypt_json(ciphertext)  →  Python 对象
```

### 8.2 密钥管理

**密钥生成**：`scripts/init_crypto.sh` 调用 `shared/crypto.py` 的 `load_or_create_key()` 函数生成 Fernet 密钥。

```bash
# init_crypto.sh 关键逻辑
KEY_FILE="$HOME/ai-assistant-system/.crypto_key"
# 若密钥已存在则跳过（防止覆盖导致历史数据无法解密）
[ -f "$KEY_FILE" ] && exit 0
# 生成密钥并设置权限
python3 -c "from shared.crypto import load_or_create_key; load_or_create_key()"
chmod 0600 "$KEY_FILE"
# 加密已有的对话历史文件
for f in logs/chat_history_*.json; do
    encrypt_file("$f")
done
```

**密钥存储**：密钥以纯文本形式存储在项目根目录的 `.crypto_key` 文件中，文件权限设为 0600（仅文件所有者可读写）。

**密钥安全要求**：

- 密钥文件不得提交到版本控制（.gitignore 已排除）
- 密钥文件不得包含在备份归档中（daily_backup.sh 已排除）
- 密钥丢失将导致所有已加密数据不可恢复
- 密钥轮换需先解密全部历史数据，再使用新密钥重新加密

### 8.3 版本控制排除

`.gitignore` 配置排除以下敏感文件和目录：

```gitignore
# 加密密钥（绝不提交）
.crypto_key

# 环境配置（含飞书密钥和 API 密钥）
config/settings.yaml
**/.env

# 运行时数据
logs/
backups/

# 虚拟环境
venv/
assistants/*/venv-*/

# 二进制依赖
shared/whisper.cpp/
llama.cpp/
```

### 8.4 文件路径安全

**白名单校验**：4号AI 文件助理在执行任何文件操作前，从 `config/whitelist.yaml` 加载对应助手的 `allowed_paths` 和 `denied_paths`，对用户提供的路径进行校验：

1. 展开路径中的 `~` 和 `.` 为绝对路径
2. 检查路径是否在 `allowed_paths` 范围内
3. 检查路径是否匹配 `denied_paths` 中的任何模式
4. 拒绝访问系统目录（/etc, /var, /System, /Library）和敏感目录（~/.ssh, ~/.config, ~/.gnupg, ~/.aws, ~/.kube）

**输入消毒**：用户消息内容在写入对话历史前，通过 JSON 序列化确保特殊字符被正确转义，防止注入攻击。文件名参数通过 `Path` 对象处理，避免路径遍历（如 `../../../etc/passwd`）。

### 9.2 恢复流程

```

│     tar -xzf <备份文件> -C $HOME                         │
│     → 写入还原时间戳到 .restore_stamp                    │
│                                                         │
│  6. 重启服务                                             │
│     bash scripts/start_all_services.sh                  │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

**安全机制**：恢复前自动备份当前项目（prev_ 前缀），即使恢复错误也可从 prev_ 备份回滚。恢复完成后写入 `.restore_stamp` 时间戳，用于验证恢复状态。

### 9.3 RTO/RPO 目标

| 指标 | 目标 | 实现方式 |
|------|------|----------|
| RTO（恢复时间目标） | <= 30 分钟 | restore.sh 一键还原：停服 → 备份当前 → 解压 → 重启 |
| RPO（恢复点目标） | <= 24 小时 | 每日 03:00 全量备份，最大数据丢失不超过 24 小时 |

**RTO 分解**：

| 步骤 | 预估耗时 |
|------|----------|
| 列出备份并确认 | 1 分钟 |
| 停止服务 | 2 分钟 |
| 备份当前项目 | 5 分钟 |
| 解压还原 | 5 分钟 |
| 重启全部服务 | 10 分钟 |
| 验证服务可用性 | 5 分钟 |
| 合计 | ~28 分钟 |

### 9.4 备份完整性验证

备份脚本执行后输出备份文件路径和大小，管理员可通过以下方式验证：

1. 检查备份文件是否存在且大小合理（应 > 1MB）
2. 执行 `tar -tzf <备份文件> | head -20` 验证归档结构完整
3. 在测试环境执行还原，验证关键数据（对话历史、生活数据、知识库）可正常加载
