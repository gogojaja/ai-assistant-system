## 1. 文档概述

本文档基于 C4 模型（Simon Brown）的第二层——容器视图（Container View），将系统上下文图中的"三角色 AI 助理系统"单一黑盒展开为多个内部容器。在 C4 模型中，"容器"指可独立部署、独立运行的技术单元（如 Web 服务、守护进程、数据存储、子进程引擎等），每个容器有独立的技术栈和职责边界。

**视图目的**：
- 展示系统内部容器的组成、职责与技术栈
- 明确容器之间的依赖关系与通信方式
- 为开发视图（代码包结构）和部署视图（物理拓扑）提供中间层映射

**目标受众**：开发者、架构评审人员

## 7. 容器职责详解

### 7.1 C-01 Flask Callback Server（主回调服务）

```
┌─────────────────────────────────────────────────────┐
│  Flask Callback Server (:5101)                      │
│  venv-callback                                      │
├─────────────────────────────────────────────────────┤
│                                                     │
│  职责：                                             │
│  · 接收飞书 Webhook 事件（POST /webhook）            │

│  · 消息类型识别（文本/语音/文件/事件）                │
│  · 消息路由分发（前缀/关键词 → 角色调度）             │
```

## 11. 容器设计决策摘要

| 决策ID | 决策内容 | 影响容器 | 理由 |
|--------|----------|----------|------|
| CD-001 | 三角色模块作为同进程模块而非独立服务 | C-02~C-04 | 个人系统并发低，同进程 import 避免进程间通信开销 |
| CD-002 | 推理后端抽象为独立容器，单一 ollama 后端（ADR-007） | C-07 | 本地推理隐私/离线优先，无云端兜底 |
| CD-003 | cloudflared 仅暴露 :5101 单入口 | X-01, C-01 | 统一入口分发，避免多端口暴露风险 |
| CD-004 | whisper.cpp 作为按需子进程而非常驻服务 | C-08 | 语音消息低频，按需启动节省内存 |
| CD-005 | 数据存储使用本地文件 + Fernet 加密 | C-05 | 无数据库依赖，部署简单，隐私优先 |
| CD-006 | 配置完全外部化至 YAML 文件 | C-06 | 配置外部化，支持主/测试环境切换 |
| CD-007 | Monitor Script 作为独立 Bash 守护进程 | C-09 | 原生 Shell 进程管理，无 Python 依赖，故障隔离 |
| CD-008 | 每个助手独立 venv 隔离 | 全部 Python 容器 | 依赖冲突隔离，单助手故障不影响其他 |

> 详细 ADR 记录见 `03_决策/` 目录。
