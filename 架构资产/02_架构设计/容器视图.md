## 1. 文档概述

本文档基于 C4 模型（Simon Brown）的第二层——容器视图（Container View），将系统上下文图中的"五角色 AI 助理系统"单一黑盒展开为多个内部容器。在 C4 模型中，"容器"指可独立部署、独立运行的技术单元（如 Web 服务、守护进程、数据存储、子进程引擎等），每个容器有独立的技术栈和职责边界。

**视图目的**：
- 展示系统内部容器的组成、职责与技术栈
- 明确容器之间的依赖关系与通信方式
- 为开发视图（代码包结构）和部署视图（物理拓扑）提供中间层映射

**目标受众**：开发者、架构评审人员

## 11. 容器设计决策摘要

| 决策ID | 决策内容 | 影响容器 | 理由 |
|--------|----------|----------|------|
| CD-001 | Flask Callback 与 File Bot Server 分离为两个独立容器 | C-01, C-02 | 故障隔离，文件操作不影响主消息路由 |
| CD-002 | 五角色模块作为同进程模块而非独立服务 | C-03~C-07 | 个人系统并发低，同进程 import 避免进程间通信开销 |
| CD-003 | 推理后端抽象为独立容器，单后端 | C-10 | 平衡性能（云端）与隐私/离线（本地），降级机制保障可用性 |
| CD-004 | whisper.cpp 作为按需子进程而非常驻服务 | C-11 | 语音消息低频，按需启动节省内存 |
| CD-005 | 数据存储使用本地文件 + Fernet 加密 | C-08 | 无数据库依赖，部署简单，隐私优先 |
| CD-006 | 配置完全外部化至 YAML 文件 | C-09 | 配置外部化，支持主/测试环境切换 |
| CD-007 | Monitor Script 作为独立 Bash 守护进程 | C-12 | 原生 Shell 进程管理，无 Python 依赖，故障隔离 |
| CD-008 | 每个助手独立 venv 隔离 | 全部 Python 容器 | 依赖冲突隔离，单助手故障不影响其他 |
