| 降级策略 | ollama 不可用时返回明确提示文本（无云端兜底） |

## 3. Webhook 接口设计

### 3.1 POST /webhook、/webhook_chat — 飞书事件回调主入口

**服务进程**：Flask Callback Server（端口 5101）

**功能描述**：接收飞书开放平台推送的事件回调，处理 challenge 验证请求，并对消息事件进行异步分发处理。`/webhook` 与 `/webhook_chat` 为同一处理函数的别名路由。

#### 3.1.1 请求格式

| 属性 | 值 |
|------|-----|
| Method | POST |
| Path | `/webhook` 或 `/webhook_chat` |
| Content-Type | `application/json; charset=utf-8` |
| 认证方式 | 飞书签名验证（可选，见第 10 章） |

**Challenge 验证请求体**（飞书配置 Webhook 时发送）：

```json
{
  "challenge": "ajls384kdjx98XX",
  "token": "xxxxxx",
  "type": "url_verification"
}
```

**事件回调请求体**（Schema 2.0 格式）：

```json
{
  "schema": "2.0",
  "header": {
    "event_id": "e2a1b3c4-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
    "event_type": "im.message.receive_v1",
    "create_time": "1700000000000",
    "token": "xxxxxx",
    "app_id": "cli_xxxxxxxx",
    "tenant_key": "xxxxxxxx"
  },
  "event": {
    "sender": {
      "sender_id": {
        "open_id": "ou_xxxxxxxxxxxxxxxx",
        "user_id": "xxxxxxxx",
        "union_id": "on_xxxxxxxxxxxxxxxx"
      },
      "sender_type": "user"
    },
    "message": {
      "message_id": "om_xxxxxxxxxxxxxxxx",
      "root_id": "om_xxxxxxxxxxxxxxxx",
      "parent_id": "om_xxxxxxxxxxxxxxxx",
      "create_time": "1700000000000",
      "chat_id": "oc_xxxxxxxxxxxxxxxx",
      "chat_type": "p2p",
      "message_type": "text",
      "content": "{\"text\":\"你好\"}",
      "mentions": []
    }
  }
}
```

**消息类型与 content 字段映射**：

| message_type | content JSON 结构 | 说明 |
|--------------|-------------------|------|
| `text` | `{"text": "用户消息内容"}` | 文本消息 |
| `audio` | `{"file_key": "file_v3_xxxx"}` | 语音消息（opus 格式） |
| `file` | `{"file_key": "file_v3_xxxx", "file_name": "doc.docx"}` | 文件消息 |
| `image` | `{"image_key": "img_v3_xxxx"}` | 图片消息 |

#### 3.1.2 响应格式

**Challenge 验证响应**（检测到 `challenge` 字段时立即返回）：

```json
{
  "challenge": "ajls384kdjx98XX"
}
```

**事件接收响应**（异步处理，立即返回）：

```json
{
  "code": 0,
  "msg": "success"
}
```

> **设计约束**：飞书要求 Webhook 在 3 秒内返回 HTTP 200，因此事件处理逻辑通过 `threading.Thread` 异步执行，主线程立即返回。

#### 3.1.3 事件处理流程

```
收到 POST 请求
     │
     ├─ 请求体为空？ ──是──► 返回 400 {"code": 400, "msg": "empty body"}
     │
     ├─ 包含 "challenge" 字段？ ──是──► 返回 {"challenge": "..."}
     │
     └─ 启动异步线程 handle_event(data)
            │
            ├─ 解析 schema 2.0 / 1.0 格式
            ├─ 过滤非 im.message.receive_v1 事件
            ├─ 提取 message_type / content / message_id / open_id
            │
            ├─ message_type == "text"
│   ├─ 前缀 #办公 ──► process_office_text()
            │   ├─ "转PPT" ──► process_office_text("转PPT")
            │   ├─ 日程/健康/旅行/锻炼/工作/帮助/看板 ──► life process()
            │   └─ 默认 ──► process_message()  (1号AI 闲聊)
            │
            ├─ message_type == "audio"
            │   └─ 启动线程 ──► process_voice_message(file_key, message_id, open_id)
            │
            ├─ message_type == "file"
            │   └─ 启动线程 ──► process_document_file(file_key, message_id, open_id, file_name)
            │
            └─ 其他类型 ──► 记录日志并忽略
```

#### 3.1.4 错误码

| HTTP 状态码 | code | msg | 触发条件 |
|-------------|------|-----|----------|
| 200 | 0 | success | 正常接收事件 |
| 200 | — | — | Challenge 验证通过（返回 challenge JSON） |
| 400 | 400 | empty body | 请求体为空或 JSON 解析失败 |

|------|-----|

**Callback Server（:5101）**：

```json
{
  "status": "ok"
```

## 4. 推理后端接口设计

### 4.1 POST /v1/chat/completions — OpenAI 兼容聊天 API

**适用后端**：ollama serve（单一 ollama 后端，ADR-007）

**功能描述**：以 OpenAI Chat Completions 兼容格式调用推理后端，支持流式（SSE）和非流式两种模式。系统默认使用流式模式以实现逐 token 输出。

#### 4.1.1 请求格式

| 属性 | 值 |
|------|-----|
| Method | POST |
| Path | `/v1/chat/completions`（ollama） |
| Content-Type | `application/json` |
| 认证方式 | 无（本地 ollama） |
| 超时设置 | 60 秒连接超时，流式读取无总超时 |
| 重试策略 | 连接失败重试 3 次，间隔 1.5 秒 |

**请求体参数**：

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| `model` | string | 是 | — | 模型标识，由 `get_backend_config()` 决定 |
| `messages` | array | 是 | — | 消息数组，遵循 OpenAI 格式 |
| `stream` | boolean | 否 | `true` | 是否流式返回，系统默认 `true` |
| `temperature` | float | 否 | `0.7`（闲聊）/ `0.3`（办公） | 采样温度 |
| `max_tokens` | integer | 否 | `2048`（闲聊）/ `1024`（办公） | 最大生成 token 数 |

**messages 数组元素结构**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `role` | string | 消息角色：`system` / `user` / `assistant` |
| `content` | string | 消息内容 |
**请求示例**：

```json
{
  "model": "qwen2.5:7b",
  "messages": [{"role": "user", "content": "你好"}],
  "stream": true
}
```

#### 4.1.2 响应格式（流式 SSE）

**Content-Type**：`text/event-stream`

**SSE 数据帧结构**：

```
data: {"id":"chatcmpl-xxx","object":"chat.completion.chunk","created":1700000000,"model":"qwen2.5:7b","choices":[{"index":0,"delta":{"role":"assistant"},"finish_reason":null}]}

data: {"id":"chatcmpl-xxx","object":"chat.completion.chunk","created":1700000000,"model":"qwen2.5:7b","choices":[{"index":0,"delta":{"content":"你"},"finish_reason":null}]}

data: {"id":"chatcmpl-xxx","object":"chat.completion.chunk","created":1700000000,"model":"qwen2.5:7b","choices":[{"index":0,"delta":{"content":"好"},"finish_reason":null}]}

data: {"id":"chatcmpl-xxx","object":"chat.completion.chunk","created":1700000000,"model":"qwen2.5:7b","choices":[{"index":0,"delta":{"reasoning_content":"用户在打招呼"},"finish_reason":null}]}

data: [DONE]
```

**delta 字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `role` | string | 仅首帧出现，值为 `assistant` |
| `content` | string | 正式回复内容片段（逐 token 增量） |
| `reasoning_content` | string | 推理过程内容片段（部分模型如 DeepSeek-R1 提供） |
| `finish_reason` | string | `null` 表示未结束，`stop` 表示正常结束 |

**客户端拼接逻辑**：

```
full_content = ""
full_reasoning = ""

for line in response.iter_lines():
    if not line or not line.startswith("data: "):
        continue
    data_str = line[6:]
    if data_str.strip() == "[DONE]":
        break
    chunk = json.loads(data_str)
    delta = chunk["choices"][0]["delta"]
    if delta.get("content"):
        full_content += delta["content"]
    if delta.get("reasoning_content"):
        full_reasoning += delta["reasoning_content"]

# 优先使用 content，为空时从 reasoning_content 提取
if full_content:
    return clean_reply(full_content)
elif full_reasoning:
    return extract_from_reasoning(full_reasoning)
```

#### 4.1.3 响应格式（非流式兜底）

当流式响应未收到任何内容时，系统回退到非流式调用：

```json
{
  "id": "chatcmpl-xxx",
  "object": "chat.completion",
  "created": 1700000000,
  "model": "qwen2.5:7b",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "你好！有什么我可以帮助你的吗？",
        "reasoning_content": ""
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 50,
    "completion_tokens": 20,
    "total_tokens": 70
  }
}
```

#### 4.1.4 后端选择配置

后端由 `config/settings.yaml` 配置驱动，`get_backend_config()` 读取逻辑如下：

**配置文件** (`config/settings.yaml`)：

```yaml
# 本地推理（单一 ollama 后端，ADR-007）
backend: ollama
ollama_port: 11434                 # 本地 ollama 推理端口
ollama_model: qwen2.5:7b
```

**后端选择优先级**：

```
get_backend_config()
     └─ 默认 ──► backend = "ollama"
                 port = ollama_port (11434)
                 model = ollama_model (qwen2.5:7b)
```

**API URL 构造规则（单一 ollama 后端）**：

| 后端 | API URL | 模型示例 |
|------|---------|----------|
| ollama | `http://localhost:{ollama_port}/v1/chat/completions` | `qwen2.5:7b` |

#### 4.1.5 错误处理与降级策略

```
call_api() / talk()
     │
     ├─ 构造请求体，发送 POST 请求
     │
     ├─ requests.ConnectionError？
     │   ├─ 重试次数 < 3 ──► 等待 1.5 秒，重试
     │   └─ 重试次数 = 3 ──► 返回 "抱歉，AI 服务暂时不可用，请稍后重试。"
     │
     ├─ HTTP 状态码 != 200？
     │   ├─ 记录错误日志（状态码 + 响应体前 500 字符）
     │   ├─ 重试次数 < 3 ──► 等待 1.5 秒，重试
     │   └─ 重试次数 = 3 ──► 返回降级提示
     │
     ├─ 流式拼接后 content 为空？
     │   ├─ reasoning_content 非空 ──► extract_from_reasoning() 提取
     │   └─ reasoning_content 也为空 ──► _fallback_with_postprocess() 非流式兜底
     │
     └─ 非流式兜底也失败 ──► 返回 "抱歉，AI 服务暂时不可用，请稍后重试。"
```

**降级场景表**：

| 场景 | 触发条件 | 降级行为 |
|------|----------|----------|
| 后端不可达 | ollama 连接拒绝 | `wake_model()` 唤醒或返回降级提示 |
| 本地后端进程被挂起 | `pgrep` 检测到进程状态含 `T`（SIGSTOP） | `wake_model()` 发送 SIGCONT (signal 18) 唤醒 |
| 本地后端未启动 | 连续 3 次连接失败 | 返回降级提示文本 |
| 流式无内容 | content 和 reasoning 均为空 | 回退非流式调用 |
| 非流式也无内容 | 兜底调用仍失败 | 返回错误提示 |
| 联网功能不可用 | 天气/翻译/搜索 API 超时 | 返回明确降级提示（如"天气服务暂时不可用"） |

#### 4.1.6 错误码

| HTTP 状态码 | 含义 | 客户端处理 |
|-------------|------|------------|
| 200 | 请求成功 | 解析 SSE 流 |
| 400 | 请求参数错误（如 messages 格式不合法） | 记录日志，返回降级提示 |
| 401 | API Key 无效（仅 ollama） | 检查配置 |
| 429 | 请求频率超限 | 等待后重试 |
| 500 | 后端内部错误 | 重试 3 次后降级 |
| 503 | 服务不可用 | 检查后端进程是否运行 |

## 5. 飞书开放平台接口设计

### 5.1 认证机制

#### 5.1.1 获取 tenant_access_token

**接口**：`POST /open-apis/auth/v3/tenant_access_token/internal`

**功能描述**：使用飞书应用的 App ID 和 App Secret 获取租户级别访问令牌。系统通过 `shared/feishu_api.py` 的 `get_tenant_access_token()` 函数封装，支持自动缓存和过期刷新。

| 属性 | 值 |
|------|-----|
| Method | POST |
| URL | `https://open.feishu.cn/open-apis/auth/v3/tenant_access_token/internal` |
| Content-Type | `application/json` |
| 超时 | 10 秒 |

**请求体**：

```json
{
  "app_id": "cli_xxxxxxxxxxxx",
  "app_secret": "xxxxxxxxxxxxxxxxxxxxxxxxxx"
}
```

**响应体**：

```json
{
  "code": 0,
  "msg": "ok",
  "tenant_access_token": "t-xxxxxxxxxxxxxxxxxxxxxxxxxx",
  "expire": 7200
}
```

**缓存策略**：

| 属性 | 说明 |
|------|------|
| 缓存位置 | 模块级变量 `_token_cache`（内存） |
| 过期判断 | `expires_at > now + 60`（提前 60 秒刷新） |
| 刷新触发 | 首次调用或缓存过期时自动请求新 token |

**凭证来源**：环境变量 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`，从 `shared/feishu-bot/.env` 加载。

### 5.2 POST /open-apis/im/v1/messages — 发送消息

**功能描述**：向指定用户或群聊发送文本消息、文件消息或互动卡片消息。由 `send_message()` 和 `send_file_message()` 函数封装。

| 属性 | 值 |
|------|-----|

### 5.6 飞书 API 速率限制

飞书开放平台对 API 调用有速率限制，系统作为个人应用（1-3 用户）实际触发限流的概率极低。以下为关键接口的限流参考：

| API 接口 | 限流策略 | 系统应对 |
|----------|----------|----------|
| 发送消息 (`/im/v1/messages`) | 5 次/秒（单个应用） | 个人系统 QPS 远低于限流，无需特殊处理 |
| 获取 token (`/auth/v3/tenant_access_token/internal`) | 500 次/分钟 | 使用内存缓存，仅在过期时刷新 |
| 上传文件 (`/im/v1/files`) | 50 次/分钟 | 文件上传为低频操作 |
| 下载文件 (`/im/v1/messages/{id}/resources/{key}`) | 50 次/分钟 | 文件下载为低频操作 |

> **限流处理策略**：若收到 HTTP 429 响应，记录告警日志。当前版本不实现自动退避重试，因个人系统并发量极低。

系统通过以下子进程命令管理推理后端进程的挂起与唤醒：

## 10. 接口安全设计

### 10.1 飞书 Webhook 签名验证

#### 10.1.1 验证机制

飞书开放平台在推送事件回调时，通过 HTTP Header 携带签名信息，系统可据此验证请求来源合法性。

**签名相关 Header**：

| Header 名称 | 说明 |
|-------------|------|
| `X-Lark-Request-Timestamp` | 请求时间戳（毫秒） |
| `X-Lark-Request-Nonce` | 请求随机串 |
| `X-Lark-Signature` | 签名值 |

**签名计算规则**：

```
signature = sha256(timestamp + nonce + encrypt_key + body)
```

其中 `encrypt_key` 为飞书应用配置的 Encrypt Key，`body` 为请求原始体。

#### 10.1.2 当前实现状态

| 属性 | 说明 |
|------|------|
| 当前状态 | 未启用签名验证（v1.0 阶段简化部署） |
| 启用方式 | 在飞书开发者后台设置 Encrypt Key，在 `callback_server.py` 中增加签名校验逻辑 |
| 安全影响 | 未启用签名验证时，任何能访问 Webhook URL 的请求均可伪造事件 |
| 缓解措施 | Webhook URL 通过 cloudflared 隧道暴露，URL 本身具有随机性；系统为个人使用，攻击面有限 |

#### 10.1.3 启用签名验证的实施计划

```python
# 计划在 callback_server.py 中增加的验证逻辑
import hashlib

def verify_feishu_signature(request, encrypt_key: str) -> bool:
    timestamp = request.headers.get("X-Lark-Request-Timestamp", "")
    nonce = request.headers.get("X-Lark-Request-Nonce", "")
    signature = request.headers.get("X-Lark-Signature", "")
    body = request.get_data(as_text=True)
    # 时间戳防重放（5 分钟窗口）
    if abs(int(time.time() * 1000) - int(timestamp)) > 300000:
        return False
    computed = hashlib.sha256(f"{timestamp}{nonce}{encrypt_key}{body}".encode()).hexdigest()
    return computed == signature
```

### 10.3 速率限制策略

#### 10.3.1 系统定位与限流需求

系统为个人优先的本地应用，典型使用场景为 1-3 人日常使用，并发量极低。因此速率限制策略以"最小化"为原则，仅在必要场景实施。

#### 10.3.2 限流策略矩阵

| 接口 | 限流需求 | 策略 | 理由 |
|------|----------|------|------|
| Webhook (/webhook) | 不需要 | 无限流 | 飞书平台已有推送频率限制；个人使用 QPS 极低 |
| 推理后端 API | 不需要 | 无限流 | 本地后端单用户独占；ollama 自身有限流 |

| 文件上传/下载 | 不需要 | 无限流 | 低频操作 |

#### 10.3.3 异常流量处理

| 场景 | 检测方式 | 处理 |
|------|----------|------|
| 短时间内大量 Webhook 请求 | 日志监控异常频率 | 记录告警，不自动限流（个人系统误报风险高） |
