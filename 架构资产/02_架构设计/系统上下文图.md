## 1. 文档概述

本文档基于 C4 模型（Simon Brown）的第一层——系统上下文（System Context），描述五角色 AI 助理系统在其运行环境中的整体定位。系统上下文图将整个系统抽象为单一"黑盒"，聚焦展示系统与外部参与者（人）及外部系统之间的交互关系，不涉及系统内部结构。

**视图目的**：
- 为所有相关方（用户、开发者、运维方）提供系统全局认知
- 明确系统边界，界定哪些能力由本系统提供、哪些由外部系统提供
- 作为后续容器视图（C4 Level 2）和组件视图（C4 Level 3）的顶层上下文

**目标受众**：所有相关方（用户、开发者、运维方、架构评审人员）

## 4. 外部实体清单

### 4.1 外部参与者

| 编号 | 实体名称 | 实体类型 | 描述 | 与系统的关系 | 交互方式 |
|------|----------|----------|------|-------------|----------|
| E-01 | 飞书用户（Feishu User） | 人（参与者） | 通过飞书 App 与系统交互的终端用户，通常为 1-3 名授权个人用户 | 系统的唯一人类用户，通过飞书 Bot 发送指令并接收回复 | 间接交互：通过飞书 App → 飞书开放平台 → 本系统 |

### 4.2 外部系统

| 编号 | 实体名称 | 实体类型 | 描述 | 与系统的关系 | 交互方式 | 协议/接口 |
|------|----------|----------|------|-------------|----------|----------|
| E-02 | 飞书开放平台（Feishu Open Platform） | 外部系统（SaaS） | 字节跳动提供的飞书开放平台，提供 Bot API v2.0，包括事件订阅、消息发送、文件资源等能力 | 系统的唯一消息入口和出口；所有用户交互均通过飞书 Bot 完成 | 双向：入站 Webhook 事件推送 + 出站 API 调用 | HTTPS / JSON / Webhook |
| E-03 | 本地 ollama（Cloud Inference Router） | 外部系统（SaaS） | 云端推理路由服务，提供 OpenAI 兼容接口，支持多模型路由，端口  | 系统的默认推理后端，提供闲聊、文档摘要等 AI 推理能力 | 出站调用：系统主动请求推理 | HTTPS / JSON / SSE 流式 |
| E-04 | 天气 API（Weather API） | 外部系统（SaaS） | 天气查询服务，支持 wttr.in 和和风天气两种数据源 | 为闲聊助理提供天气查询增强能力 | 出站调用：系统主动查询 | HTTPS / JSON |
| E-05 | 翻译 API（Translate API） | 外部系统（SaaS） | 文本翻译服务，基于 deep-translator 库，支持 Google/百度等多引擎 | 为闲聊助理提供多语言翻译能力 | 出站调用：系统主动请求翻译 | HTTPS / JSON |
| E-06 | 搜索 API（Search API） | 外部系统（SaaS） | 网页搜索服务，支持 Google/DuckDuckGo 等搜索引擎 | 为闲聊助理提供实时信息搜索能力 | 出站调用：系统主动搜索 | HTTPS / JSON |

## 5. 系统边界界定

### 5.1 系统边界内（本系统提供的能力）

| 能力域 | 说明 |
|--------|------|
| 消息接入 | Flask 回调服务接收飞书 Webhook 事件，路由分发到各角色 |
| 闲聊对话 | 1号AI 提供流式对话、历史管理、知识库检索 |
| 办公文档 | 2号AI 提供 Word/Excel/PPT 处理与 AI 摘要 |
| 生活管理 | 3号AI 提供日程/健康/旅行/锻炼/工作管理 |
| 文件操作 | 4号AI 提供文件传输/管理/安全控制 |
| 系统运维 | 5号AI 提供系统监控/服务/进程/备份管理（待建） |
| 语音识别 | whisper.cpp 本地语音转文字 |
| 数据加密 | Fernet 对称加密，本地存储 |
| 推理后端切换 | 三后端（ollama）可切换与降级 |
| 服务守护 | bash 守护脚本，进程监控与自动拉起 |

### 5.2 系统边界外（外部系统提供的能力）

| 能力域 | 提供方 | 说明 |
|--------|--------|------|
| 用户交互界面 | 飞书开放平台 / 飞书 App | 系统无独立 UI，所有交互通过飞书 Bot |
| 消息传输 | 飞书开放平台 | Webhook 推送 + Send API |
| 文件存储（云端） | 飞书开放平台 | 用户上传的文件暂存于飞书云端，系统按需下载 |
| 云端 AI 推理 | ollama | 默认推理后端，提供多模型路由 |
| 天气数据 | 天气 API 服务商 | wttr.in / 和风天气 |
| 翻译服务 | 翻译 API 服务商 | deep-translator / 百度翻译 |
| 搜索服务 | 搜索 API 服务商 | Google / DuckDuckGo |
| 公网隧道 | Cloudflare（cloudflared） | 提供公网入口，将飞书 Webhook 转发至本地 |

### 5.3 边界决策说明

| 决策 | 理由 |
|------|------|
| 飞书 Bot 作为唯一交互入口 | 个人系统无需独立 UI，飞书提供成熟的移动端体验 |
| 推理能力部分外置 | 云端推理性能最优但数据出境；本地推理隐私优先但性能受限，故采用单后端 |
| 联网增强能力外置 | 天气/翻译/搜索为标准 SaaS 服务，无需自建 |
| 数据存储完全内置 | 隐私优先，所有用户数据（对话历史/知识库/备份）加密存储于本地 |

## 8. 设计约束与假设

### 8.1 约束

| 约束类型 | 约束内容 | 来源 |
|----------|----------|------|
| 交互约束 | 所有用户交互仅通过飞书 Bot，无独立 Web UI | 架构策略分析报告 §1.3 |
| 平台约束 | macOS 14+ Apple Silicon M 系列 | 架构策略分析报告 §1.3 |
| 网络约束 | 核心功能需离线可用，联网功能优雅降级 | 架构策略分析报告 §1.3 |
| 安全约束 | 用户数据加密存储于本地，不依赖外部数据库 | 架构策略分析报告 §1.3 |

### 8.2 假设

| 假设 | 说明 |
|------|------|
| 飞书开放平台 SLA 稳定 | 飞书 Bot API v2.0 服务可用性由字节跳动保障 |
| 本地 ollama可用 | 默认推理后端，不可用时自动降级至本地 |
| 外部 API 可达 | 天气/翻译/搜索 API 服务商持续提供服务，断网时优雅降级 |
| 用户数量有限 | 个人系统 1-3 名授权用户，无高并发需求 |
