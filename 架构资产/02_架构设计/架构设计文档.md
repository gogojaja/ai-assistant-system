### 2.4 逻辑视图设计规则

| 规则 | 说明 |
|------|------|
| 单一职责 | 每个类/模块仅承担一个明确职责，禁止 God Object |
| 依赖方向 | 上层（assistants）→ 下层（shared），禁止反向依赖 |
| 无交叉依赖 | 三角色助手之间禁止直接调用，仅通过 shared 层间接共享 |
| 接口隔离 | 各助手对外暴露的入口函数固定，内部实现可自由演进 |

### 3.3 并发与线程模型

Flask Callback Server 采用**多线程模型**处理并发请求：

```
[飞书 Webhook 请求]
       │
       ▼
┌─────────────────┐
│ Flask 主线程     │  ← 接收 HTTP 请求，立即返回 200
│ (WSGI)          │
└────────┬────────┘
         │ threading.Thread(target=handle_event, args=(data,))
         ▼
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│ Worker 线程 1    │     │ Worker 线程 2    │     │ Worker 线程 N    │
│ handle_event()  │     │ handle_event()  │     │ handle_event()  │
│                 │     │                 │     │                 │
│ → 消息路由       │     │ → 消息路由       │     │ → 消息路由       │
│ → 调用处理器     │     │ → 调用处理器     │     │ → 调用处理器     │
│ → 推理后端调用   │     │ → 推理后端调用   │     │ → 推理后端调用   │
│ → 飞书回复       │     │ → 飞书回复       │     │ → 飞书回复       │
└─────────────────┘     └─────────────────┘     └─────────────────┘
```

| 并发特性 | 设计决策 | 理由 |
|----------|----------|------|
| 线程模型 | 每个请求创建独立线程 | 飞书 Webhook 要求 3 秒内返回 200，异步处理避免超时 |
| 线程安全 | 对话历史文件读写无锁（per-user 隔离） | 个人系统并发量低（1-3人），per-user 文件天然隔离 |
| 连接池 | requests 库默认连接池 | 推理后端调用为短连接，无需连接池优化 |
| GIL 限制 | 接受 GIL 瓶颈 | CPU 密集型推理在后端进程，Flask 仅做 IO 转发 |

### 3.4 进程通信机制

| 通信路径 | 协议 | 数据格式 | 同步/异步 | 异常处理 |
|----------|------|----------|-----------|----------|
| 飞书 → cloudflared → Flask | HTTPS | JSON | 同步（Webhook） | 3秒超时返回200，异步处理 |
| Flask → 推理后端 | HTTP | JSON（OpenAI 兼容） | 同步（流式 SSE） | 超时重试 + 降级 |
| Flask → whisper.cpp | subprocess | 文件（wav） | 同步 | 子进程超时 kill |
| Flask → 文件系统 | POSIX FS | JSON/加密文件 | 同步 | 文件读写异常捕获 |
| Flask → 飞书 API | HTTPS | JSON | 异步（fire-and-forget） | 失败重试 3 次 |

## 7. 架构设计决策摘要

| 决策ID | 决策内容 | 理由 | 影响 |
|--------|----------|------|------|
| D-001 | 采用 Flask 多线程模型处理 Webhook | 飞书要求 3 秒响应，异步处理避免超时 | 需要 per-user 文件隔离保证线程安全 |
| D-002 | 三角色完全解耦，仅通过 shared 层共享 | 减少耦合、便于独立演进 | 依赖方向统一为 assistants→shared |
| D-003 | 单一 ollama 后端（ADR-007） | 本地优先，隐私/离线保证，无云端兜底 | 需要后端抽象层 |
| D-004 | 本地文件 + Fernet 加密存储 | 无数据库依赖，部署简单 | 数据量增长后需评估 SQLite 迁移 |
| D-005 | 每个助手独立 venv 隔离 | 依赖冲突隔离，故障隔离 | 依赖管理复杂度增加 |
| D-006 | cloudflared 隧道暴露本地服务 | 无需公网 IP，自动 HTTPS | 隧道断开需监控告警 |
| D-007 | SIGSTOP/SIGCONT 管理推理进程 | 闲置释放内存，请求时唤醒 | 唤醒延迟约 1-3 秒 |

> 详细 ADR 记录见 `03_架构决策/ADR/` 目录。
