## 1. 文档概述

本文档对三角色 AI 助理系统进行 C4 模型 Component 级别的组件设计，基于架构设计文档的逻辑视图与开发视图，将系统分解为接入层、业务层、基础设施层和运维层四个层次的可复用组件。每个组件以统一表格格式描述其职责、接口、依赖、生命周期和通信方式，并附组件依赖关系图与生命周期管理表，为开发实现和后续维护提供精确的组件契约约束。

本文档覆盖以下设计原则：

- **单一职责原则（SRP）**：每个组件仅承担一个明确定义的功能域
- **开放-封闭原则（OCP）**：通过接口抽象支持扩展，不修改现有组件
- **依赖倒置原则（DIP）**：业务层依赖基础设施层抽象接口，非具体实现
- **接口隔离原则（ISP）**：组件对外暴露最小必要接口集
- **无环依赖原则（ADP）**：组件间依赖关系为有向无环图（DAG）

## 3. 接入层组件设计

接入层负责接收飞书 Webhook 事件、解析消息类型、按路由规则分派到对应业务处理器，并提供健康检查和后端代理能力。

### 3.1 CallbackServer

| 设计项 | 内容 |
|--------|------|
| 组件职责 | 飞书回调服务主入口，接收 Webhook 事件并异步分派到业务处理器；提供健康检查端点；注册 Dashboard 蓝图 |
| 对外接口 | HTTP 端点：`POST /webhook`、`POST /webhook_chat`（飞书事件回调）；`GET /health`（健康检查）。所有 POST 端点支持飞书 `challenge` 应答 |
| 依赖组件 | MessageHandler（`process_message`）、VoiceHandler（`process_voice_message`）、DocumentHandler（`process_document_file`、`process_office_text`）、LifeAssistant（`process`）、FeishuAPI（`send_message`）、Dashboard 蓝图（`dashboard_bp`）；标准库 `threading`（异步分派） |
| 生命周期 | 由 `scripts/start_all_services.sh` 或 `scripts/start_chat_bots.sh` 启动；`app.run(host="0.0.0.0", port=5101)` 阻塞运行；端口从 `config/settings.yaml` 的 `callback_port` 读取，默认 5101；由 `scripts/stop_chat_bots.sh` 或 `scripts/stop_all_services.sh` 终止 |
| 通信方式 | 入站：飞书开放平台通过 HTTPS Webhook 推送事件（POST JSON）；内部分派：`threading.Thread` 异步调用处理器（非阻塞响应）；处理器通过 `FeishuAPI.send_message()` 回复用户 |

**路由与事件分派逻辑：**

CallbackServer 的 `handle_event()` 函数解析飞书事件 schema 2.0 格式，提取 `event_type`、`message_type`、`open_id`、`chat_id`，按消息类型分派：

- **challenge 应答**：检测到 `challenge` 字段时立即返回，完成飞书域名验证
- **text 消息**：解析 `content.text`，按前缀/关键词路由到对应业务助理
- **audio 消息**：提取 `file_key`，新线程调用 `process_voice_message()`
- **file 消息**：提取 `file_key` 和 `file_name`，新线程调用 `process_document_file()`
- **其他类型**：记录日志并忽略

### 3.3 MessageRouter

| 设计项 | 内容 |
|--------|------|
| 组件职责 | 消息路由逻辑组件（内嵌于 CallbackServer 的 `handle_event()` 函数），根据消息类型和文本前缀/关键词将事件路由到对应业务助理处理器 |
| 对外接口 | 函数级接口：`handle_event(data: dict)` —— 解析飞书事件 JSON，分派到对应处理器 |
| 依赖组件 | ChatAssistant.MessageHandler、ChatAssistant.VoiceHandler、OfficeAssistant.DocumentHandler、LifeAssistant（`process`）、FeishuAPI（`send_message`） |
| 生命周期 | 随 CallbackServer 进程存活，无独立生命周期管理；每次 Webhook 事件触发一次 `handle_event()` 调用 |
| 通信方式 | 函数调用（同进程同步路由判断 + 异步线程执行处理器）；处理器通过 FeishuAPI 回复用户 |

**前缀路由表：**

| 消息类型 | 路由条件 | 目标处理器 | 说明 |
|----------|----------|------------|------|
| text | 前缀 `#办公 ` 或等于 `#办公` | `DocumentHandler.process_office_text()` | 2号AI 办公助理 |
| text | 等于 `转PPT` 或前缀 `转PPT ` | `DocumentHandler.process_office_text("转PPT")` | 文档转 PPT 快捷命令 |
| text | 前缀属于 `日程`、`健康`、`旅行`、`锻炼`、`工作`、`帮助`、`看板` | `LifeAssistant.process()` + `FeishuAPI.send_message()` | 3号AI 生活助手 |
| text | 以上均不匹配（默认） | `MessageHandler.process_message()` | 1号AI 闲聊助理 |
| audio | `message_type == "audio"` | `VoiceHandler.process_voice_message()`（新线程） | 语音消息处理 |
| file | `message_type == "file"` | `DocumentHandler.process_document_file()`（新线程） | 文档文件分析 |
| 其他 | `message_type` 不在上述列表 | 日志记录并忽略 | 未知类型过滤 |

## 4. 业务层组件设计

业务层包含三个角色助理（1号闲聊/2号办公/3号生活），每个助理封装独立功能域，通过基础设施层组件与外部服务交互。

### 4.1 ChatAssistant（1号AI 闲聊助理）

#### 4.1.1 MessageHandler

| 设计项 | 内容 |
|--------|------|
| 组件职责 | 文本消息总处理器，根据消息内容分发到闲聊、天气、翻译、搜索、知识库、提示词管理、身份识别等功能；管理 per-user 对话历史（JSON 持久化）；组装引用回复头并分块发送超长消息 |
| 对外接口 | `process_message(user_text: str, target_id: str, open_id: str, receive_id_type: str)` —— 处理用户文本消息，调用 `send_message` 回复 |
| 依赖组件 | ChatMain（`talk`、`trim_history`、`_save_custom_prompt`、`_load_custom_prompt`）、Utils（`get_weather`、`normalize_city_for_weather`、`translate_text`、`handle_search`、`get_city_from_config_or_default`、`search_web`）、KnowledgeBase（`search`、`list_docs`）、FeishuAPI（`send_message`、`update_message`） |
| 生命周期 | 随 CallbackServer 进程常驻；每次文本消息触发一次 `process_message()` 调用；对话历史按 `open_id` 持久化到 `logs/chat_history_{open_id}.json`，轮次计数器持久化到 `logs/chat_counter_{open_id}.txt` |
| 通信方式 | 函数调用（同进程同步执行）；历史存储：JSON 文件读写；回复发送：FeishuAPI `send_message` / `update_message`；超长回复：自动按段落分块，首块 `update_message`，后续块分别 `send_message` |

**指令路由逻辑：**

| 用户输入模式 | 处理逻辑 |
|-------------|---------|
| `帮助` / `你能做什么` 等 | 返回帮助指南 `_HELP_TEXT` |
| `clear` | 清空当前用户对话历史 |
| `设置提示词: <内容>` | 保存自定义提示词到 `prompts/{open_id}.txt` |
| `查看提示词` | 读取并返回当前自定义提示词 |
| `重置提示词` / `删除提示词` | 删除自定义提示词文件 |
| `查知识 <关键词>` / `知识库` | 调用 `KnowledgeBase.search()` 或 `list_docs()` |
| `翻译 <内容>` | 调用 `Utils.translate_text()` |
| 包含天气关键词 | 解析城市和时间偏移，调用 `Utils.get_weather()` |
| `我是/我叫...` 身份类问题 | 从历史中查找用户自我介绍并回复 |
| 默认 | 自动联网搜索 → `ChatMain.talk()` 流式对话 → 格式化回复 |

#### 4.1.2 ChatMain

| 设计项 | 内容 |
|--------|------|
| 组件职责 | 1号AI 闲聊检索主入口，负责流式调用推理后端 API（ollama），拼接 content 与 reasoning_content，执行 5 层回复提取策略，注入系统上下文（时间、城市、提示词、格式指南），后处理格式化 |
| 对外接口 | `talk(messages: list, open_id: str) -> str` —— 流式调用模型返回回复；`trim_history(messages: list) -> list` —— 裁剪历史保留最近 10 轮；`handle_search(user_input) -> str` —— 联网搜索；`handle_local_search(user_input) -> str` —— 本地知识库检索；`show_help() -> str` —— 帮助信息 |
| 依赖组件 | chat 模块（`load_history`、`save_history`、`clear_history`）、search 模块（`search_web`、`search_archive`、`format_results`）；标准库 `requests`、`yaml` |
| 生命周期 | 随 ChatAssistant 模块加载；每次对话触发 `talk()` 调用；连接重试 3 次（间隔 1.5 秒）；流式读取 SSE 直到 `[DONE]` |
| 通信方式 | 出站：`requests.post()` 流式 POST 到推理后端 API（`/v1/chat/completions`）；模型进程管理：`pgrep`/`ps`/`os.kill(SIGCONT)` 唤醒被 SIGSTOP 挂起的模型进程；历史持久化：`chat.py` 的 JSON 文件读写 |

**回复提取策略（5 层降级）：**

| 层级 | 策略 | 说明 |
|------|------|------|
| 1 | content 字段拼接 | 优先使用流式返回的 `delta.content` |
| 2 | reasoning 引号提取 | content 为空时，从 `reasoning_content` 中查找 `回应说/回答是/答案是` 后的引号内容 |
| 3 | reasoning 最终回答 | 查找 `最终回答` 附近的引号内容 |
| 4 | reasoning 段落提取 | 取最后一段有完整含义的句子 |
| 5 | 非流式兜底 | 流式完全失败时，发起非流式请求并提取最终回答 |

#### 4.1.3 VoiceHandler

| 设计项 | 内容 |
|--------|------|
| 组件职责 | 语音消息处理全流程：下载 opus 音频 → 转换为 wav → whisper.cpp 语音识别 → 识别文本交由 MessageHandler 处理；临时文件自动清理 |
| 对外接口 | `process_voice_message(file_key: str, message_id: str, open_id: str)` —— 完整处理语音消息 |
| 依赖组件 | FeishuAPI（`download_file`、`send_message`）、SpeechUtils（`transcribe_audio`、`convert_opus_to_wav`）、MessageHandler（`process_message`） |
| 生命周期 | 随 CallbackServer 进程常驻；每次语音消息触发新线程调用 `process_voice_message()`；临时文件（.opus/.wav）在 `finally` 块中自动清理 |
| 通信方式 | 入站：FeishuAPI `download_file()` 下载飞书音频到临时文件；处理：SpeechUtils `convert_opus_to_wav()` + `transcribe_audio()`；出站：`MessageHandler.process_message()` 回复用户 |

### 4.2 OfficeAssistant（2号AI 办公助理）

#### 4.2.1 DocumentHandler

| 设计项 | 内容 |
|--------|------|
| 组件职责 | 文档处理总入口，负责文件下载、格式识别（docx/xlsx/pptx）、大小校验、分发到对应处理器、组装回复、管理文档缓存（用于"转PPT"）；处理 `#办公` 文本命令（PPT 生成、转PPT）；启动文件夹监控 |
| 对外接口 | `process_document_file(file_key, message_id, open_id, file_name)` —— 处理文档文件消息；`process_office_text(cmd_text, open_id, target_id, receive_id_type)` —— 处理办公文本命令；`generate_excel_summary(data_text, structure_hint) -> (summary, is_ai)` —— 生成 Excel 摘要 |
| 依赖组件 | FeishuAPI（`download_file`、`send_message`、`send_file_message`）、BackendUtils（`call_api`）、WordProcessor、ExcelProcessor、PPTGenerator（`generate_via_pandoc`、`generate_from_text`、`check_pandoc`）、DocumentSummarizer、FolderMonitor（`start_monitor`） |
| 生命周期 | 随 CallbackServer 进程常驻；文档缓存 `_doc_cache` 为进程内字典，超过 100 条自动清空；文件夹监控在模块导入时自动启动 |
| 通信方式 | 入站：FeishuAPI `download_file()` 下载到临时文件；处理：本地文件解析 + BackendUtils `call_api()` 生成 AI 摘要；出站：FeishuAPI `send_message()` 回复文本，`send_file_message()` 发送生成的 PPT 文件 |

**文件格式处理路由：**

| 文件后缀 | 处理器 | 处理内容 | 大小限制 |
|----------|--------|----------|----------|
| `.docx` | WordProcessor + DocumentSummarizer | 提取文本/标题/表格信息 + AI 摘要 | 30 MB |
| `.xlsx` | ExcelProcessor + `generate_excel_summary()` | 结构分析 + 数据提取 + AI/规则摘要 | 15 MB |
| `.pptx` | `_extract_pptx_text()` | 提取幻灯片文本 + 内容预览 | 30 MB |

| 设计项 | 内容 |

| 通信方式 | 本地文件读取（`Path.read_text()` / `Document()` 构造函数）；无网络通信 |

#### 4.2.4 PPTGenerator

| 设计项 | 内容 |

### 5.1 FeishuAPI

| 设计项 | 内容 |
|--------|------|
| 组件职责 | 飞书开放平台 API 封装，提供 tenant_access_token 获取与缓存、消息发送（文本/卡片/文件）、消息更新、文件下载与上传功能 |

- Token 缓存策略：`_token_cache` 字典存储 token 和过期时间，提前 60 秒判断过期并自动刷新

| ExcelProcessor | `ExcelProcessor(file_path)` 构造 | `_load()` 调用 `openpyxl.load_workbook()` | `analyze()` / `get_data_text()` | DocumentHandler `finally` 块中删除临时文件 |
| PPTGenerator | 函数调用时 | 解析输入文本为结构化幻灯片数据 | `generate_presentation()` / `generate_via_pandoc()` 生成 PPTX | 函数返回输出路径；Pandoc 临时 Markdown 文件自动清理 |
| MessageHandler | CallbackServer `handle_event()` 调用时 | 加载 per-user 对话历史（JSON）；解析用户意图 | 分发到对应功能（闲聊/天气/翻译/搜索/知识库）；流式调用模型；格式化回复 | 保存对话历史到 JSON 文件；函数返回 |

### 7.3 数据持久化生命周期

| 数据类型 | 存储位置 | 创建时机 | 更新时机 | 清理/归档 |
|----------|----------|----------|----------|-----------|
| 对话历史 | `logs/chat_history_{open_id}.json` | 首次对话 | 每轮对话后 `_save_history()` | 用户发送 `clear` 命令时删除 |
| 轮次计数 | `logs/chat_counter_{open_id}.txt` | 首次对话 | 每轮对话后 `_save_counter()` | 用户发送 `clear` 命令时删除 |
| 自定义提示词 | `prompts/{open_id}.txt` | 用户设置提示词时 | 用户重新设置时覆盖 | 用户删除提示词时 `unlink()` |
| 知识库索引 | `data/knowledge_index[_{user_id}].json` | 首次检索时自动构建 | 文档导入/删除时重建 | 手动删除文档后重建 |
| 日程数据 | `data/life/schedules.json` | 首次添加日程 | 每次增删改操作 | 无自动清理 |
| 健康数据 | `data/life/health.json` | 首次记录 | 每次记录操作 | 无自动清理 |
| 旅行数据 | `data/life/travels.json` | 首次创建旅行 | 每次增删改操作 | 无自动清理 |
| 锻炼数据 | `data/life/workouts.json` | 首次创建计划 | 每次增删改操作 | 无自动清理 |
| 工作数据 | `data/life/works.json` | 首次创建工作项 | 每次增删改操作 | 无自动清理 |
| 加密密钥 | `.crypto_key` | 首次使用 CryptoManager 时 | 仅手动重新初始化 | `scripts/init_crypto.sh` 重新生成 |
| 办公文件 | `data/office/` | PPT 生成时 | 文件名带时间戳 | FolderMonitor 监控变更 |
